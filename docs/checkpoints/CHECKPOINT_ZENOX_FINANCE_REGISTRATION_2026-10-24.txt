1. OBJECTIF UTILISATEUR
Remplacer l'écran de démonstration par un parcours réel :
- création d'un compte Supabase Auth et confirmation d'e-mail ;
- connexion, déconnexion, récupération et réinitialisation du mot de passe ;
- soumission d'une organisation et suivi de la demande ;
- examen par un opérateur de plateforme autorisé ;
- activation atomique de l'organisation et du propriétaire après approbation ;
- refus avec motif, désactivation de l'organisation et révocation de l'adhésion ;
- accès au workspace financier uniquement lorsqu'un tenant et une adhésion sont ACTIVE ;
- indicateurs de facturation chargés depuis une API authentifiée et tenant-scoped.

2. IMPLÉMENTÉ SUR LA BRANCHE
- Migration 20261024000100_tenant_registration_onboarding.sql :
  - table finance_registration_requests avec RLS ENABLED + FORCED ;
  - fonctions SECURITY DEFINER pour soumission, liste et détail des demandes du propriétaire ;
  - création atomique du tenant PENDING, de l'adhésion OWNER PENDING, de la demande et de l'événement d'audit ;
  - validation de la devise active et index unique pour une seule demande PENDING par identité.
- Migration 20261024000200_platform_registration_review.sql :
  - allowlist finance_platform_operators, RLS ENABLED + FORCED ;
  - aucun accès direct aux tables pour PUBLIC, anon, authenticated ou service_role ;
  - fonctions de vérification d'opérateur, liste des demandes en attente et décision atomique ;
  - APPROVE active le tenant et l'adhésion OWNER ; REJECT désactive le tenant, révoque l'adhésion et conserve le motif ;
  - interdiction pour un opérateur d'examiner sa propre demande ;
  - chaque décision est auditée dans la même transaction ;
  - exécution autorisée uniquement par fonctions étroites côté serveur.
- Backend routes d'inscription :
  - GET /api/v1/user/registration/currencies
  - POST /api/v1/user/registration/organizations
  - GET /api/v1/user/registration/organizations
  - GET /api/v1/user/registration/organizations/:requestId
- Backend routes d'administration :
  - GET /api/v1/user/platform/me
  - GET /api/v1/user/platform/registration-requests
  - POST /api/v1/user/platform/registration-requests/:requestId/decision
- L'auth middleware vérifie l'identité auprès de Supabase Auth et expose le timestamp de confirmation d'e-mail. La soumission et les décisions exigent une session confirmée et un POST same-origin.
- Frontend RegistrationWorkspace : inscription, connexion, gestion des liens de confirmation, récupération/réinitialisation, renvoi de confirmation, soumission d'organisation et suivi de statut.
- Frontend PlatformReviewWorkspace : écran de revue visible uniquement si l'API confirme le rôle d'opérateur de plateforme.
- Le workspace financier est protégé par session et adhésion ACTIVE. Le dashboard charge depuis le backend le nombre de factures émises, les brouillons et le total brut des factures émises ; les montants restent des chaînes décimales exactes.
- Runbook d'amorçage du premier opérateur : docs/runbooks/bootstrap-first-platform-operator.md.
- Décisions d'autorisation : docs/architecture/PLATFORM_REGISTRATION_REVIEW_AUTHORIZATION.md.
- Tests ajoutés : tests de routes d'inscription et de revue, tests PostgreSQL d'intégration, test du timestamp de confirmation Auth.
